# Regex Knowledge Architecture

## Purpose

Research how comprehensive regex knowledge should be modeled, maintained, queried, versioned, and connected to evidence without duplicating the operational STRling Regex Knowledge Program.

## Important research questions

- Which entities and relationships make engine, dialect, implementation, host, API, Unicode, replacement, option, and version distinctions explicit?
- How should unknowns, conflicts, historical claims, and coverage completeness be represented?
- How should normative knowledge reference empirical observations without copying their authority?
- What publication projections can be generated without losing provenance?

## Relationship to STRling

The compiler and public reference need trustworthy knowledge projections. This program can evaluate architectures and implications, but downstream owners decide and implement integrations.

## Current evidence boundary

The [Knowledge Program](https://app.notion.com/p/3ba7d940647581a9b60dd76f67e5230e?pvs=204) defines a graph of versioned profiles, features, capabilities, relations, claim-level evidence, and coverage facets. As reviewed 2026-08-12, it is on hold pending reassessment against Regex Conformance. That workspace remains the operational knowledge authority while retained; no database is copied here.

## Related existing inquiries

- [Semantic validation and domain libraries](../../inquiries/semantic-validation-and-domain-libraries/README.md) contains historical registry material, but does not define a canonical regex knowledge model.

No dedicated inquiry has begun.

## Future research opportunities

Authority-preserving Knowledge–Conformance linkage, stable identifiers, schema evolution, completeness, conflict resolution, storage tradeoffs, and public query requirements.

## Explicit non-goals

This program does not populate regex databases, copy records, resume the paused Knowledge Program, or decide its future without owner authorization.
