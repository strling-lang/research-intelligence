# Shared Lab execution and session contract feasibility

- Role: Experiment report
- Origin: STRling Research Intelligence, AI-assisted fixture design and execution
- Published/Generated: 2026-11-20
- Source verification: Verified under current evidence standard for the stated scope
- Last reviewed: 2026-11-20
- Current status: Active input

## Decision

Share orchestration, request correlation, input/test-case revision, typed results, and session history. Preserve raw source and semantic compiler provenance as separate request variants. Treat a provider's result as evidence for one operation on one input under one identified environment. A shared match array loses information needed to represent split, replacement, cursor state, truncation, and refusal. The trial supports this bounded contract recommendation, with public qualification and downstream acceptance open.

## Method and results

The hypothesis was that the same correlation and session machinery could preserve different operation semantics and evidence origins without a provider-specific copy of session history. Its falsifiers were a lost observable when the request is saved and replayed, an invalid coordinate converted to a display span, an obsolete or mismatched response accepted as current, or a fixture promoted to live or certified evidence.

The [hand-authored expectations](../artifacts/contract-cases.json) specify 25 fixed local inputs and expected observables, including adapter refusals. The [replay](../artifacts/replay-contract.mjs) uses Node.js `RegExp` as the provider under test. Expected outputs derive from the operation definitions and direct hand calculations for each subject. This checks the projection independently of live observations. The semantic leg stores the compiler contract version, source revision, example path, semantic IR literal, and exact target profile digest. Executing compiler build, emitted artifact bytes and engine options were outside this fixture. The optional website leg imports the pinned coordinator and contracts directly from Git objects into memory, then injects a deterministic test provider. The [record](../artifacts/replay-record.json) contains the raw observations and explicitly modeled failure outcomes.

| Question | Result and evidence type |
| --- | --- |
| Search versus full-match | **Observed in Node.** On `ab`, `a\|ab` selects `a` for search and `ab` for the fixture's explicitly anchored full operation. `ab` is a substring match on `xab`, but the full operation refuses the substring and a final trailing newline. Empty input can match at `[0,0)`. ECMAScript has no dedicated full-match API in this trial. The wrapper's evidence covers this set of unflagged patterns. |
| Scan and state | **Observed in Node.** On `😀é`, empty scans returned UTF-16 starts `[0,2,3,4]` with `u` and `[0,1,2,3,4]` without it. `matchAll` begins from the explicit saved `lastIndex`. The wrapper refuses a cursor inside a surrogate pair in `u` mode. An `N+1` observation distinguishes an exactly-at-limit result from a truncated prefix. Resume remains unavailable for that prefix. |
| Replacement | **Observed in Node.** ECMAScript `$1` replacement on an ordered alternative produces `<a>b`. Replacement can return the same string with no match or with an actual replacement. Output equality cannot determine how many edits took place. The separate display cap withholds output after construction and is insufficient as a resource limit. |
| Split and extraction | **Observed in Node.** Split retains captured delimiters, nonparticipating captures, empty edge fields, and a native element limit. A Unicode-aware zero-width delimiter preserves a supplementary scalar and segments the base character and combining mark separately. Extraction distinguishes a participating empty capture and span, a nonparticipating declared group, an absent requested key, and an ordinary value. Provider-unavailable capture information is a separate fixture refusal. |
| Native versus display spans | **Observed + fixture.** Eight coordinate/encoding checks reconstructed UTF-16 ranges from a cumulative UTF-8/scalar boundary table. A real Node match returned a lone surrogate in UTF-16, and the fatal UTF-8 decoder rejected an invalid byte. Mappings from malformed text or interior UTF-8 byte boundaries were refused. On `😀abc`, the fixture's native UTF-8 `[4,7)` gives `c` if passed directly to JS `slice`; mapped UTF-16 `[2,5)` gives `abc`, the observed raw match. The Website client currently feeds span offsets into JS string decoration without unit conversion. |
| Lifecycle and wrong attribution | **Observed + fixture.** Aborting an unlinked Node worker controller left the benign worker alive until `terminate()` and an exit event. The pinned Website coordinator dropped a stale response even though its provider still delivered it, and reported a thrown failure as infrastructure failure. The same coordinator settled a response with correct generation/request/profile and mismatched operation and provider IDs. Stronger identity checks in the candidate envelope refused mismatches. Eight modeled failure outcomes covered deadline without acknowledgement, acknowledged termination, cancellation, infrastructure/runtime failure, unsupported operation, refusal, and unknown. A production deadline and resource limits remain untested. |
| Save and replay | **Observed + fixture.** One saved history retained a raw search, a semantic-to-target fixture on the same subject, and a raw scan with explicit cursor. The two bounded raw operations replayed on the pinned runtime. The semantic record remained inspectable fixture history. Nine negative checks covered unavailable provider or profile, redaction, byte changes, mismatched coordinate space, cursor, native unit, progression policy, and match limit. The digest is a byte-integrity check for this record. It provides no authorization, source authenticity, or privacy. |

For Node's relevant operations, see [ECMA-262 2025 §22.2.6 and §22.2.7](https://tc39.es/ecma262/2025/multipage/text-processing.html#sec-regexp-regular-expression-objects) and [String type](https://tc39.es/ecma262/2025/multipage/ecmascript-data-types-and-values.html#sec-ecmascript-language-types-string-type). The UTF-8 fixture is scoped to an 8-bit UTF-8 subject. PCRE2 also has 16- and 32-bit library widths. A runtime label without the API width, subject representation, and option identity is insufficient to interpret offsets. See [PCRE2 native API](https://www.pcre.org/current/doc/html/pcre2api.html). The [Encoding Standard `TextEncoder`](https://encoding.spec.whatwg.org/#interface-textencoder) takes a USVString, whose [Web IDL conversion](https://webidl.spec.whatwg.org/#es-USVString) uses scalar values. A lossy conversion of a lone surrogate cannot supply exact replay coordinates. Distinguish [DOM abort signaling](https://dom.spec.whatwg.org/#aborting-ongoing-activities), [HTML worker termination](https://html.spec.whatwg.org/multipage/workers.html#dom-worker-terminate-dev), and the distinct [Node worker termination API](https://nodejs.org/download/release/v24.4.1/docs/api/worker_threads.html#workerterminate). Browser client identification exposes compatibility and privacy-shaped values. It can support a visible best-effort label or capability probes. Exact runtime identity remains unknown without a stronger build/profile signal. See [HTML client identification](https://html.spec.whatwg.org/multipage/system-state.html#client-identification).

## Shared envelope and owner handoff

Use versioned envelopes with an immutable request identity and a run generation, independent program/test-case revisions, an explicit subject representation and coordinate space, requested operation/arguments, effective options/limits, provider identity and profile resolution, and observable outcome and evidence origin. Keep status separate from lifecycle. Tag authored raw regex with dialect/flags. Tag semantic inputs with source/IR identity and link compiler identity, compile outcome, exact target artifact/options, and relevant diagnostics. The target requested for compilation and the executing provider identity are independent fields with a compatibility check. Pin cursor/session state to its provider, profile and subject.

| Boundary | Typed fields to retain | Gap at pinned baseline and owner acceptance test |
| --- | --- | --- |
| Query result | `search` and `full-match` carry selected match or complete no-match. `scan` carries ordered prefix, completion/truncation cause, optional resume state, and declared zero-width/overlap progression. `extract` carries field projections with value and availability. | **Website + provider.** Name native versus emulated operations. Demonstrate full-match reselection, unit-qualified cursor rules, exact-at-cap versus truncated, and all four capture states in the selected provider. |
| Transformed result | `replace` carries template language, limit and output/partial state, with count or edit provenance only when observed. `split` carries elements and element kind or native projection with its separate split limit. | **Website + provider.** The v1 match collection lacks these operation payloads. Reproduce captured delimiters, unmatched captures, zero-width splits and unchanged replacement with different edit provenance. Budget transformation work before exposing it. |
| Coordinate projection | Native source/result ranges carry subject identity, unit and endpoints. Display ranges carry a derived mapping/outcome with source model. | **Website + provider.** Check well-formed and malformed subjects, combining marks, supplementary characters and markers inside surrogate pairs. Reject undefined conversions and keep native offsets visible. |
| Identity and lifecycle | Correlate schema, run generation, request, operation, provider/build and exact profile. Keep deadline, cancellation and confirmed termination distinct. Track timeout/crash, refusal, unknown, and unsupported separately. | **Website + provider.** Drop or diagnose operation/provider mismatch at the response boundary. Require a demonstrable stop mechanism and bounded resource use with stale-response tests. Verify browser and any remote isolation under the actual deployment policy. |
| Compile and explanation | Semantic compile results, matched/no-match observations, and explanation conclusions each retain their own evidence class. Match-phase status is conditional on the actual provider result. | **Compiler + Website.** Carry existing artifact and explanation contracts through the UI. The bounded no-match contract has independent `proven`, `likely`, `unknown` and `unavailable` classifications. A compile result or explanation is insufficient evidence that a target provider ran. [Compiler no-match contract](https://github.com/strling-lang/strling/blob/eba5dad3de3fa620eb1ea13e0514d02f4b23e288/spec/explanations/no-match/1.0/README.md) |
| History and replay | Persist original raw or semantic authoring data, request parameters, effective provider/build, prior outputs and dependency revisions. Identify replay that matches exactly, is unavailable, or reopens historical output. | **Website.** Verify import consent and redaction, unknown build, output continuity, exact cross-surface reopen, immutable revisions and adjudicated replay. Keep local-only and shared storage options explicit. The trial saves exact record bytes. It never processes untrusted session uploads. |
| Interactive qualification | Provider-specific version, operations/options/coordinate declarations, execution quotas, limits, isolation, lifecycle evidence, and an explicit interactive evidence origin. | **Website + provider.** Qualify actual browser/runtime deployments independently of Conformance. For hosted execution, verify that worker policy, credentials and evidence stores are isolated from trusted Conformance. Keep certified compatibility tied to authorized checkpoint provenance. [Conformance authority](https://github.com/strling-lang/regex-conformance/blob/3285cc9fa8310df0af00fa50724d65531e0695d9/README.md#authority-boundaries) |

One generic `matched` result is a poor fit for transformations. Fully separate Lab frameworks would retain semantics but duplicate orchestration and history. The tested middle choice shares the record and lifecycle while requiring operation payloads and dialect/compile provenance at the boundaries. Evaluate user comprehension and consent in the formative-study protocol before making user-effect claims.

## Reproduction

From a clean Research Intelligence checkout, use Node.js `24.4.1` with built-ins only. No installation, random seed, external libraries, network, or secret inputs are required during replay. The harness is fixed to at most 32 cases, with patterns of at most 40 UTF-16 units, subjects of at most 24, templates of at most 8, and at most nine scan observations per case. Worker startup has a five-second test bound and explicit cleanup. Run:

```sh
node --no-warnings inquiries/regex-lab-interaction-model/artifacts/replay-contract.mjs
node --no-warnings inquiries/regex-lab-interaction-model/artifacts/replay-contract.mjs --website ../website
```

The second command requires a local Website Git object at the exact pinned revision. It reads Git objects and adds the `website` result section. Compare the resulting JSON with the [replay record](../artifacts/replay-record.json). Both runs of the full command yielded identical output. A standalone replay from an empty temporary directory containing only the runner and its fixtures matched the record outside the `website` section.
